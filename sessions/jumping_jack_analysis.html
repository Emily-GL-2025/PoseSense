Geometry → confirmation → state → repetition

How a valid jumping jack is measured

A source-backed explanation of the current workout analyzer: what the keypoints must do in space, how long a posture must persist, and why a plausible-looking movement can still produce no repetition.

Based on workout/analysis/jumping_jack.py and its live recording pipeline. Defaults inspected on 2026-10-07. This is an implementation guide, not a general exercise-form standard.

Learning the counter? Start with the separate flowchart guide, then the pseudocode guide and line-by-line Python guide. Each uses the same complete worked example.

Are keypoints absolute or normalized? YOLO returns image-pixel coordinates. This application converts them to normalized image coordinates before counting or saving. The counter then compares body-relative ratios. The abs() in its formulas means the magnitude of a difference; it does not mean the coordinates are stored as absolute pixels.

01 · “Valid” means a recognized sequence

The program does not identify a jumping jack from one frame. It confirms a CLOSED posture, then an OPEN posture, then a CLOSED posture again. The final confirmed OPEN → CLOSED transition adds one repetition.

UNKNOWN → confirmed CLOSED → confirmed OPEN → confirmed CLOSED = +1 rep

CLOSED

Both wrists are sufficiently below their own shoulders, and the horizontal ankle separation is small enough relative to shoulder width.

OPEN

Both wrists are sufficiently above their own shoulders, and the horizontal ankle separation is large enough relative to shoulder width.

It is a 2D posture-cycle heuristic, not a physical jump detector. It does not test airtime, foot contact with the ground, knee or elbow angles, straight arms, wrist height above the head, symmetry of the motion, speed of the jump, or an energy signal. A non-jumping motion could count if it satisfies the same poses and sequence.

“No rep” can therefore mean four different things: the spatial gates never passed together; a candidate posture was too brief; the cycle was not armed from CLOSED; or a continuity/validity failure reset the phase.

02 · Where the measurements come from

workout_session.py loads yolo26m-pose.pt and calls model.track(..., persist=True) once per processed camera frame. YOLO estimates the 17 joints; the tracker associates current observations with IDs. The main controller selects one ID, while the separate CPU counter decides whether that person's pose completes a repetition. YOLO itself does not output a jumping-jack count.

A PosePacket contains frame_index, a session-relative timestamp, selected_track_id, a [17,3] pose, present, a continuity generation, and the main process’s accepted_reps. The counter uses pose timestamps—not the time at which a worker happens to execute the code.

Sources: tracking.py · tracked_people, line 40; session.py · process_frame, line 98; worker.py · analysis_main, line 60.

The denominator is result.orig_shape, the actual original image dimensions. It is not the neural network's imgsz=640, the displayed window size, or the person's bounding box. The installed pose predictor maps network predictions back to the original frame before the application divides them.

# workout/tracking.py — actual conversion, with explanatory comments
# Each selected person has 17 rows: pixel x, pixel y, confidence.
poses = data[indices.tolist()].detach().cpu().numpy().astype(np.float32, copy=True)
height, width = result.orig_shape    # original camera frame, not network input
poses[:, :, 0] /= width              # x is now a fraction of image width
poses[:, :, 1] /= height             # y is now a fraction of image height
# Column 2 (confidence) is unchanged. Equivalent x/y units to keypoints.xyn.

The origin is the image’s upper-left corner. Larger x means farther right on the image; larger y means lower on the image. “Left” and “right” joint names mean the person’s anatomical sides, not the left and right of the screen. There is no side-specific correction in these formulas.

Normalization removes image-size units. The analyzer then divides horizontal distances by a horizontal body reference and vertical distances by a vertical body reference. Consequently, image width cancels from the ankle ratio, and image height cancels from the wrist/span ratio. It does not compute Euclidean distances from a mixture of normalized x and y. Normalization does not correct occlusion, perspective, body rotation or inference errors.

One bad required joint invalidates the whole posture

All x, y and confidence values for these six joints must be finite, and each confidence must be ≥ 0.5. Equality at the confidence threshold is accepted. The shared clean_pose() function replaces unreliable x/y coordinates with NaN, while retaining confidence. The analysis and recorder receive these cleaned coordinates.

# workout/packets.py — actual validity test
points = pose[list(indices)]
return bool(
    np.isfinite(points).all()
    and (points[:, 2] >= confidence).all()
)

The classifier adds two scale-validity checks: shoulder width must be at least 0.01 in normalized x, and the mean ankle y must be below the mean shoulder y, giving a vertical span strictly greater than zero. The analyzer itself does not add an x/y ∈ [0,1] gate. Do not confuse display clipping with analysis validity.

Lowering replay confidence cannot recover erased coordinates. If the recording already contains NaN x/y, a lower threshold in debug.py still leaves the joint invalid. The original image and pre-mask coordinates are not present in the NPZ.

04 · The spatial formulas

Explore the six-joint pose

Move a wrist, widen the feet, or lower one joint's confidence. The three OPEN gates or three CLOSED gates must pass together. This panel classifies one synthetic frame; temporal confirmation comes next.

0.20 is an example measurement, not a fixed value in the application. The live counter measures shoulder width from every pose: abs(left_shoulder_x - right_shoulder_x). Because those x coordinates were already divided by image width in tracked_people(), this difference equals shoulder separation in pixels / image width. The counter uses it as the reference for ankle spread; it does not divide it by image width again.

Current frame: CLOSED

    Inspect the six normalized [x, y, confidence] rows

    Shoulder y = 0.35; ankle y = 0.85; body span = 0.50. Anatomical left is drawn on the viewer's right. The controls set intended decimal values; measurements use float32 keypoints, like the application. Blue and green lines are separate entry limits, not additional joints.

    Let S, W and A denote shoulder, wrist and ankle. Subscripts L and R denote anatomical sides. All the following quantities are recomputed from the current pose; shoulder width and body span are not calibrated once or smoothed over time.

    shoulder_width = |S_L.x − S_R.x|
    body_span = (A_L.y + A_R.y − S_L.y − S_R.y) / 2
    ankle_ratio = |A_L.x − A_R.x| / shoulder_width
    left_delta = W_L.y − S_L.y
    right_delta = W_R.y − S_R.y
    margin = 0.10 × body_span
    GateCLOSEDOPEN
    Left wristleft_delta > +marginleft_delta < −margin
    Right wristright_delta > +marginright_delta < −margin
    Feetankle_ratio ≤ 1.0ankle_ratio ≥ 1.4
    CombinationAll three CLOSED tests in the same processed sample.All three OPEN tests in the same processed sample.

    Wrist comparisons are strict; ankle comparisons are inclusive. A wrist exactly on its boundary does not pass. Ankles exactly at ratio 1.0 pass the CLOSED foot test; ankles exactly at 1.4 pass the OPEN foot test. Passing a foot test alone never classifies a posture.

    A worked numerical example

    Suppose shoulder x coordinates are 0.40 and 0.60, both shoulder y values are 0.40, and both ankle y values are 0.90. Then width = 0.20, span = 0.50, and margin = 0.05.

    • OPEN wrist requirement: both wrist y values must be less than 0.35. CLOSED wrist requirement: both must be greater than 0.45.
    • OPEN ankle requirement: horizontal spread must be at least 0.28. CLOSED ankle requirement: spread must be at most 0.20.
    • Wrists at y = 0.10 and ankles at x = 0.25 / 0.75 give ratio 2.5: OPEN.
    • Wrists at y = 0.65 and ankles at x = 0.45 / 0.55 give ratio 0.5: CLOSED.
    • Wrists up but an ankle ratio of 1.20 give neither posture, because the feet are not open enough and the arms are not closed.

    These are conceptual decimal calculations. Production poses are float32, so values extremely close to a boundary can be affected by floating-point rounding.

    06 · Hysteresis: the same pose can retain different histories

    Hysteresis is state memory between distinct entry conditions. The counter does not switch CLOSED ↔ OPEN at a single ankle ratio or a single shoulder-height boundary. It uses separated thresholds, and retains the last confirmed phase while passing through an intermediate region.

    Raw posture, pending posture and stable phase are separate

    ConceptMeaningExample
    Raw postureWhat the current pose’s spatial gates say: CLOSED, OPEN or no classification.This frame has raised wrists and wide feet → OPEN.
    Pending postureThe matching candidate currently being timed, with pending_since.OPEN has been seen for 33 ms; not confirmed yet.
    Stable phaseThe remembered exercise phase: UNKNOWN, CLOSED or OPEN.Still CLOSED until OPEN is confirmed for at least 60 ms.

    With valid geometry in the dead band, classify() returns None without resetting the stable phase. Then update() clears pending. If the same intermediate pose is reached from CLOSED, the phase stays CLOSED. If reached from OPEN, it stays OPEN. That dependence on history is the hysteresis.

    The code retains pending after a posture is confirmed, so its displayed duration can exceed 60 ms even when the stable phase already agrees. Another posture starts a new timer; a dead-band or reset condition clears it.

    “None” has two causes with different effects. Invalid required joints or degenerate scale also return None, but first call reset_phase(). The debugger labels these cases INVALID versus DEAD BAND; those are diagnostic labels, not extra values in the production ExerciseState enum.

    When a classified posture differs from pending, the counter starts a new timer at that packet’s timestamp. The posture is eligible to update the stable phase when:

    packet.timestamp − pending_since ≥ confirm_seconds = 0.06 seconds

    All processed observations within that candidate run must classify as the same posture. A different classified posture starts a new run; a dead-band sample cancels the run. Invalidity or a continuity break resets the phase as well.

    Ideal regular sampling examples, with the first matching observation at t = 0.
    Processed sample rateObservation timesFirst ≥ 60 ms confirmation
    30 Hz0, 33.3, 66.7 ms3rd matching sample
    60 Hz0, 16.7, 33.3, 50.0, 66.7 ms5th matching sample
    15 Hz0, 66.7 ms2nd matching sample

    There is no fixed “three frames” rule. There is also no separate minimum rep duration, no maximum duration for the whole CLOSED → OPEN → CLOSED cycle, and no automatic phase expiration while valid intermediate poses keep arriving with allowed gaps.

    “Continuous” means continuous in the observations the worker processed. Two matching samples 70 ms apart can confirm a posture, provided the packet gap is permitted and continuity is unchanged. The code cannot prove what happened between them. A dropped dead-band sample can change the live result relative to an all-samples replay. Recorded generation changes protect against missed loss/recovery notifications, but cannot reconstruct every skipped posture.

    08 · Continuity, resets and count ownership

    EventStable phase / pendingCounter total

    The sample-gap test compares the current packet timestamp with the previous processed packet, not the previous valid pose and not necessarily the previous camera frame. The timestamp/frame bookkeeping is updated even for missing or invalid poses. A gap of exactly 0.5 seconds is permitted; a larger gap is not.

    Why a generation exists in addition to a track ID

    The main controller increments generation at session start, when the selected person is lost, and when the person is reacquired. Even if the worker’s mailbox overwrites the missing-person packet, the next packet carries a different generation. The worker then abandons the interrupted cycle. Reacquiring the same tracker ID is still a continuity break.

    confirmed CLOSED → confirmed OPEN → person lost → UNKNOWN
    person returns still OPEN → remains UNKNOWN
    must confirm CLOSED, then OPEN, then CLOSED again to add a new rep

    reset_phase() itself only changes state and pending; it does not zero the repetition total. On identity/generation changes, update() separately reseeds the worker’s count from the main process’s accepted total. That can discard a worker increment which the main process had not yet accepted before the break.

    The live count is accepted asynchronously

    SessionController.accept_status() checks that the person is tracked, the status has no error, the generation matches, and the processed frame is newer than the last accepted one but not ahead of the last submitted packet. It keeps the maximum of its current count and the accepted worker count. Final shutdown has a special tracked check based on the last packet’s presence.

    As a result, a saved per-frame rep_counts[i] is the main process’s accepted count at recording time, not necessarily the counter’s result after analyzing that exact pose. The final metadata count can reflect an additional accepted status drained at shutdown.

    Selection gestures are separate rules

    Session start uses an anatomical right-hand gesture: right wrist y < nose y and right elbow y < right shoulder y, with required-joint confidence ≥ 0.5. The hold is 2 seconds to start and 1 second to deliberately select a replacement after loss, with a 0.15-second missing-observation grace. A confidently lowered hand cancels that gesture hold. The current session target is 180 seconds (3 minutes).

    These values come from workout/gesture.py and workout/session.py. They are not jumping-jack thresholds. In particular, a raised-hand start gesture does not arm the counter: the user still needs a confirmed CLOSED posture first. Gesture grace is not an invalid-joint grace period for exercise counting.

    09 · Read the code in two layers

    The counter starts with state = UNKNOWN, rep_count = 0, and pending = None. reset_phase() restores UNKNOWN and clears the pending posture; it preserves the repetition total. Geometry decides the current posture in classify(); continuity, elapsed time and remembered state decide whether it counts in update().

    Layer A: classify the current pose

    This compact version uses the same comparisons as classify(). Variable names are expanded for readability; it is explanatory code, not a replacement file. Notice the reset in the invalid branches and its absence in the final dead-band branch.

    needed = (LEFT_SHOULDER, RIGHT_SHOULDER,
          LEFT_WRIST, RIGHT_WRIST, LEFT_ANKLE, RIGHT_ANKLE)

if not valid_keypoints(pose, needed, cfg.confidence):
    self.reset_phase()
    return None                          # INVALID: stable phase lost

width = abs(float(pose[LEFT_SHOULDER, 0] - pose[RIGHT_SHOULDER, 0]))
span = float((pose[LEFT_ANKLE, 1] + pose[RIGHT_ANKLE, 1]
              - pose[LEFT_SHOULDER, 1] - pose[RIGHT_SHOULDER, 1]) / 2)

if width < cfg.minimum_shoulder_width or span <= 0:
    self.reset_phase()
    return None                          # INVALID: unusable body scale

ratio = abs(float(pose[LEFT_ANKLE, 0] - pose[RIGHT_ANKLE, 0])) / width
left = float(pose[LEFT_WRIST, 1] - pose[LEFT_SHOULDER, 1])
right = float(pose[RIGHT_WRIST, 1] - pose[RIGHT_SHOULDER, 1])
margin = cfg.wrist_margin * span

if left > margin and right > margin and ratio <= cfg.closed_ankle_ratio:
    return ExerciseState.CLOSED
if left < -margin and right < -margin and ratio >= cfg.open_ankle_ratio:
    return ExerciseState.OPEN

return None                              # DEAD BAND: stable phase retained

    Layer B: apply continuity, confirmation and sequence

    The following is the current update() logic, with comments added to mark the stages. The early-return order matters: old frames are ignored first, identity changes take precedence over the sample-gap branch, and spatial classification happens after those checks.

    def update(self, packet: PosePacket) -> int:
    # 1. Ignore stale / duplicate work.
    if packet.frame_index <= self.last_frame:
        return self.rep_count

    # 2. Reset interrupted phase; identity changes reseed accepted reps.
    changed = (
        packet.generation != self.generation
        or packet.selected_track_id != self.track_id
    )
    if changed:
        self.reset_phase()
        self.rep_count = packet.accepted_reps
    elif (
        self.last_timestamp is not None
        and not 0
        <= packet.timestamp - self.last_timestamp
        <= self.config.max_sample_gap
    ):
        self.reset_phase()

    self.generation = packet.generation
    self.track_id = packet.selected_track_id
    self.last_timestamp = packet.timestamp
    self.last_frame = packet.frame_index

    # 3. Missing / invalid / intermediate poses are different cases.
    if not packet.present:
        self.reset_phase()
        return self.rep_count
    posture = self.classify(packet.pose)
    if posture is None:
        self.pending = None
        return self.rep_count

    # 4. Confirm a run of matching processed observations.
    if posture != self.pending:
        self.pending, self.pending_since = posture, packet.timestamp
    if packet.timestamp - self.pending_since < self.config.confirm_seconds:
        return self.rep_count

    # 5. Arm from CLOSED; count only a confirmed OPEN -> CLOSED edge.
    if self.state == ExerciseState.UNKNOWN:
        if posture == ExerciseState.CLOSED:
            self.state = ExerciseState.CLOSED
    elif posture != self.state:
        if self.state == ExerciseState.OPEN and posture == ExerciseState.CLOSED:
            self.rep_count += 1
        self.state = posture
    return self.rep_count

    A small reproducible sequence

    import numpy as np
from workout.analysis.jumping_jack import JumpingJackCounter
from workout.packets import PosePacket

def make_pose(opened):
    p = np.full((17, 3), 0.5, dtype=np.float32)
    p[:, 2] = 0.99
    p[5, :2], p[6, :2] = (0.4, 0.4), (0.6, 0.4)
    p[9, 1] = p[10, 1] = 0.1 if opened else 0.65
    p[15, :2], p[16, :2] = (
        ((0.25, 0.9), (0.75, 0.9)) if opened
        else ((0.45, 0.9), (0.55, 0.9))
    )
    return p

counter = JumpingJackCounter()
for frame in range(9):
    opened = 3 <= frame < 6       # closed x3, open x3, closed x3
    packet = PosePacket(
        frame_index=frame,
        timestamp=frame * 0.04,    # 40 ms sample spacing
        selected_track_id=7,
        pose=make_pose(opened),
        present=True,
        generation=1,
        accepted_reps=0,
    )
    counter.update(packet)
    print(frame, counter.state.value, counter.rep_count)

assert counter.rep_count == 1      # counted on the final sample at t = 0.32 s

    The first run confirms CLOSED at 0.08 s, the second confirms OPEN at 0.20 s, and the final run confirms CLOSED at 0.32 s. Changing the first three poses to OPEN does not supply the initial CLOSED phase and therefore does not produce that rep.

    10 · What an offline replay can and cannot prove

    sessions/debug.py feeds every recorded pose into the real current JumpingJackCounter, in source frame order, using recorded timestamps, presence, selected IDs and generations. It precomputes the result before playback. Seeking, displaying at 0.5× speed or skipping displayed frames cannot change that precomputed count.

    The debugger carries its own accepted repetition total across generations. It does not reproduce live status acknowledgments from the main process. The NPZ stores poses, timestamps, frame indices, presence, observed IDs, generations, accepted per-frame counts, final metadata and session events. It does not store the original camera video, the original analysis configuration, or the full sequence of worker deliveries and accepted/rejected statuses.

    Use replay to answer “which gates and state transitions does the current code produce from these stored keypoints?” Do not treat it as proof of what the person physically did, or as an exact reconstruction of a live worker schedule when packets/statuses were dropped.

    11 · A practical diagnosis order

    1. Confirm the selected person exists. Check presence, observed ID and generation. A skeleton disappearing or a new generation explains a phase reset before any exercise thresholds matter.
    2. Check all six required joints. Look for confidence below the threshold or NaN x/y. A single bad ankle can invalidate an otherwise convincing arms-up pose.
    3. Inspect the body reference. Shoulder width is horizontal, not an anatomical 3D measurement. Body rotation or a misplaced shoulder changes both ankle thresholds. A changing vertical span moves both wrist limits.
    4. Check the three gates in one frame. Both wrists and feet must agree on OPEN or CLOSED simultaneously. Independent peaks at different times do not qualify.
    5. Watch pending time, not just the raw label. OPEN for 33 ms followed by dead band is not confirmed OPEN, even if an OPEN label briefly appears.
    6. Watch stable phase. UNKNOWN cannot start from OPEN. After loss or invalidity, a fresh CLOSED phase is required. A frame may be spatially CLOSED but still have a pending timer.
    7. Inspect gaps and worker health. A > 0.5-second processed-packet gap resets the phase. Packet drops can affect which intermediate observations are seen. Check the saved worker error and forced-shutdown metadata too.
    8. Compare default replay with saved live counts. Matching final totals support the geometric/state explanation. Differences require checking source-config drift, packet delivery and status acceptance before blaming a single threshold.
    9. Change one threshold in replay only. Observe which previously blocked transitions appear. More counted reps alone does not demonstrate better accuracy; verify against the actual motion before changing production settings.
