Session authority

workout/session.py · workout/packets.py

SessionController owns WAITING, ACTIVE_TRACKED, ACTIVE_LOST, and FINISHED, plus the selected ID and 180-second timer.

  • Selection, loss, and recovery update the continuity generation.
  • Status must match the generation, be newer than the last accepted status, and not be ahead of the last submitted frame.
  • It creates the selected PosePacket, appends it to the recorder, and returns it for publication.
  • Loss records an absent pose and keeps the timer running.

Boundary: Only accepted status updates the main-process rep count and exercise phase; error status is rejected.

Why the boundaries matter

Three rules hold the system together

01

Record before publishing

SessionController.process_frame() appends the active pose to its recorder before worker.publish(). Mailbox overwrites affect analysis coverage, while the recorded history keeps that frame.

02

The main loop does not wait for analysis

Each mailbox has one shared slot. Unread values may be replaced; lock contention drops an incoming value. Worker failure is reported while pose recording continues.

03

Continuity protects the accepted count

Selection, loss, and recovery advance a generation. The main process rejects stale or incompatible status; the worker resets its partial cycle and uses the accepted rep baseline.

Data contracts · workout/packets.py

TrackedPerson

A current-frame tracker observation, extracted from the YOLO result. Each pose has 17 COCO joints with normalized x, y, and confidence.

track_id: int
pose: float32[17, 3]

PosePacket → worker

The selected pose plus its session context. clean_pose() masks unreliable x/y as NaN; an absent person produces an all-NaN pose.

frame_index, timestamp
selected_track_id, pose, present
generation, accepted_reps

AnalysisStatus → main

A count and phase proposal tagged with the analyzed frame and generation. The controller checks these tags before accepting the result.

rep_count, exercise_state
last_processed_frame, generation
processed_packets, error

Supporting modules and entry points

These tools share the runtime or counter; they are separate from the normal live path.

benchmark_workout.py + FrameMetrics

The wrapper runs the reference or workout variant, optionally feeding scripted session poses after real inference. FrameMetrics collects timings after warmup and writes JSON after shutdown when --metrics is set.

standard_import.py

A separate batch-video path reuses pose extraction and the counter configuration. It exports pose NPZs and JSON / HTML reports under standards/ for offline inspection and threshold analysis.
