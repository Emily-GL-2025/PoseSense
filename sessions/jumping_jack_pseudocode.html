Understand the rules in plain steps

Read the algorithm as plain-language pseudocode. Separate measuring one pose from confirming its phase and completing a repetition.

Current application source inspected 7 October 2026. Read the guides in order, or use the same worked example in each one.

First, separate three different questions

1. Current posture

What do the six joints say in this sample? classify() returns CLOSED, OPEN or None.

2. Pending posture

Which candidate is being timed? A matching run of processed observations must span at least 60 ms.

3. Stable phase

What does the counter remember? self.state is UNKNOWN, CLOSED or OPEN. The phase changes only after confirmation, or a reset.

UNKNOWN means “the cycle has not been armed from a confirmed CLOSED pose.” A person can look OPEN in the current sample while the stable phase remains UNKNOWN. Confirming OPEN alone cannot start a cycle.

A repetition is a remembered sequence: confirmed CLOSED → confirmed OPEN → confirmed CLOSED. Only the final OPEN → CLOSED transition adds one.

An intermediate pose does not automatically mean UNKNOWN. Valid joints that satisfy neither complete posture return None: keep the stable phase and cancel the pending timer. Invalid required joints or invalid body scale also return None, but first reset the phase to UNKNOWN. These two cases have different effects.

The actual measurements and thresholds

The input is pose[joint] = [x, y, confidence]. x is a fraction of the original image width; y is a fraction of the original image height. Smaller y is higher in the picture. The app uses shoulders (5, 6), wrists (9, 10), and ankles (15, 16). Left and right are the person's anatomical sides.

width = abs(left_shoulder.x - right_shoulder.x) span = average(ankle.y) - average(shoulder.y) feet = abs(left_ankle.x - right_ankle.x) / width left = left_wrist.y - left_shoulder.y right = right_wrist.y - right_shoulder.y margin = 0.10 * span

height in the actual code is the vertical shoulder-to-ankle span above. It is a 2D image measurement. width is measured from every current pose; there is no fixed shoulder width of 0.2.

Each of the six joints needs finite x, y and confidence, with confidence ≥ 0.5. Body scale also needs width ≥ 0.01 and span > 0. Wrist boundaries are strict; foot boundaries are inclusive.

See one easy numerical example

Example shoulders: x = 0.4 and 0.6; both y = 0.4. Example ankles: both y = 0.9. This gives width 0.2, span 0.5 and margin 0.05. These are synthetic example measurements, not fixed settings.

  • Hands up: both wrist y values must be below 0.35 numerically, meaning physically above the limit in the image.
  • Hands down: both wrist y values must be greater than 0.45.
  • Feet open: horizontal ankle separation must be at least 0.28 (= 1.4 × 0.2).
  • Feet closed: separation must be at most 0.20 (= 1.0 × 0.2).
  • Hands up with feet ratio 1.2 satisfies neither complete posture. The stable phase is preserved; the candidate timer is canceled.

Production poses are float32; values extremely close to a boundary can be affected by rounding.

Part A: describe one sample

This answers only the geometry question. Read each IF as “is this whole condition true?” Read RETURN as “stop this function and give back this answer.”

FUNCTION CHECK_POSTURE(pose):
    IF any of the six required joints is nonfinite or has confidence < 0.5:
        RESET_PHASE()                 # forget the interrupted cycle
        RETURN NO_POSTURE

    shoulder_width = abs(left shoulder x - right shoulder x)
    body_span = mean ankle y - mean shoulder y
    IF shoulder_width < 0.01 OR body_span <= 0:
        RESET_PHASE()
        RETURN NO_POSTURE

    feet_ratio = abs(left ankle x - right ankle x) / shoulder_width
    left_delta = left wrist y - left shoulder y
    right_delta = right wrist y - right shoulder y
    margin = 0.10 * body_span

    IF left_delta > margin AND right_delta > margin AND feet_ratio <= 1.0:
        RETURN CLOSED

    IF left_delta < -margin AND right_delta < -margin AND feet_ratio >= 1.4:
        RETURN OPEN

    RETURN NO_POSTURE                 # valid intermediate: preserve phase

The first two failure branches call RESET_PHASE. The final branch does not. That is why unreliable joints and a normal in-between motion have different effects.

Part B: confirm, remember, and count

This procedure runs once per packet the worker receives. Matching observations are timed using the packet timestamp. All early returns occur before the counting step.

FUNCTION PROCESS_ONE_PACKET(packet):
    IF packet.frame <= last_processed_frame:
        RETURN rep_count              # old or duplicate work

    IF packet.generation changed OR packet.selected_id changed:
        RESET_PHASE()
        rep_count = packet.accepted_reps
    ELSE IF a previous timestamp exists
            AND time since the previous packet is outside [0, 0.5 seconds]:
        RESET_PHASE()                 # keep the repetition total

    REMEMBER packet generation, selected ID, timestamp, and frame number

    IF packet says the selected person is absent:
        RESET_PHASE()
        RETURN rep_count

    current_posture = CHECK_POSTURE(packet.pose)
    IF current_posture is NO_POSTURE:
        pending_posture = NOTHING
        RETURN rep_count

    IF current_posture differs from pending_posture:
        pending_posture = current_posture
        pending_start_time = packet.timestamp

    IF packet.timestamp - pending_start_time < 0.06 seconds:
        RETURN rep_count              # not confirmed yet

    # From here, the current posture is confirmed.
    IF stable_phase is UNKNOWN:
        IF current_posture is CLOSED:
            stable_phase = CLOSED     # now the cycle is armed
        # Confirmed OPEN leaves UNKNOWN unchanged.

    ELSE IF current_posture differs from stable_phase:
        IF stable_phase is OPEN AND current_posture is CLOSED:
            rep_count = rep_count + 1 # the only increment in this function
        stable_phase = current_posture

    RETURN rep_count

Only one line increases the count. It is reached after the posture is confirmed and only when the remembered phase was OPEN and the new posture is CLOSED.

The count stays at zero until 0.32 s. The first CLOSED run arms the cycle. The OPEN run opens it. The final CLOSED run finishes it. Staying CLOSED afterward does not add another rep.

40 ms is the chosen example interval. The code uses elapsed packet timestamps, not a fixed number of frames. At another sample rate the number of samples needed can differ. The timer remains stored after confirmation until a new candidate or reset changes it.

Check your understanding

First sample is OPEN. Does the phase become OPEN?

No. The phase starts UNKNOWN. Even a confirmed OPEN run leaves it UNKNOWN. A confirmed CLOSED run must arm it first.

Stable phase is OPEN. A valid in-between pose arrives. Does it reset?

No. CHECK_POSTURE returns NO_POSTURE without resetting. PROCESS_ONE_PACKET clears pending. Stable phase remains OPEN. A later confirmed CLOSED run can finish the rep.

Stable phase is OPEN. An ankle has confidence 0.2. Does the next CLOSED run finish that rep?

No. The invalid ankle resets the phase to UNKNOWN. The next confirmed CLOSED run only arms a new cycle. OPEN and then CLOSED are still needed.

Why does CLOSED for another 60 ms not add a second rep?

The stable phase is already CLOSED. There is no OPEN → CLOSED transition, so the increment condition is false.

A generation is the main controller's continuity marker. It changes on selection, loss and recovery, even if the tracker ID is unchanged. After a reset the person must establish CLOSED again before another full cycle can count.

reset_phase() does not zero the count. It changes only the stable phase and pending candidate. Identity/generation changes separately reseed the count from the main process's accepted total.
